# Haydar Pack V58-RC — GitHub Staging

هذه حزمة الواجهة المرشحة للاختبار وليست نسخة الإنتاج.

## قبل النشر

1. انشر حزمة Apps Script المرفقة كمشروع **جديد مستقل** عن مشروع الإنتاج.
2. افتح `config.js` واستبدل القيمة المؤقتة برابط `/exec` الخاص ببيئة V58-RC فقط.
3. ارفع هذه الملفات إلى فرع staging منفصل، مثل `v58-rc`.
4. لا تضع رابط Apps Script الإنتاجي القديم داخل هذه الحزمة.

## حدود الأمان

- لا يوجد مسار يرفع JSON المتصفح كاملًا فوق Google.
- التخزين المحلي Cache للحالة المؤكدة، ومسودات/عمليات معلقة، وتشخيصات فقط.
- النجاح لا يظهر إلا بعد تأكيد Apps Script لنفس `mutationId`.
- لا توجد طباعة Chrome رسمية؛ كل مستند PDF يطلب من endpoint الخادم.
- `config.js` متعمد أن يحتوي Placeholder حتى لا تتصل نسخة RC بالإنتاج بالخطأ.

## لو ظهر في V57 «حركات في انتظار الرفع: 1»

- لا تضغط زر مزامنة V57 ولا تمسح بيانات الموقع.
- افتح RC من مسار staging على نفس أصل GitHub Pages ومن نفس Browser Profile حتى يستطيع رؤية التخزين المحلي القديم.
- RC يقارن السجل القديم بالحالة المؤكدة. لو تطابقا يسجل بصمة إثبات فقط؛ ولو اختلفا يوقف أي حفظ جديد ويعرض نوع الفرق.
- نزّل «حزمة استرداد V57». الحزمة محلية ولا تُرسل إلى Apps Script تلقائيًا.
- لا يوجد أي كود في RC يرفع `hayder_bags_app` أو `hayder_pack_sync_pending_v37` كحالة كاملة، ولا يحذفهما.

## التحقق البصري

تعرض صفحة «حالة النظام والنسخ الاحتياطي» نسخة التطبيق، نسخة Backend، المراجعة، البصمة، آخر حفظ مؤكد، العمليات المعلقة، Apps Script، ونسخة Service Worker.
